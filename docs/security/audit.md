# Security audit

This page is the threat model of WA MCP: what can go wrong, what the software does about it, and which
tests check it. It complements [Security and privacy](../security.md), which describes the protection for
users. Status values:

- **Mitigated**: the measure is in place and tested.
- **Partly**: the measure lowers the risk; some of it remains and is documented.
- **Accepted**: a known limit that the software does not try to fix, with advice in the docs.
- **Out of scope**: needs code execution as your user or is a WhatsApp matter.

Test names are Go tests in `bridge/` (`go test ./...`) and Python tests in `sdk/python/tests` and
`server/tests` (`pytest`).

## Threats

| Threat | Measures | Status | Covered by |
| --- | --- | --- | --- |
| Session theft: a copy of the store folder (backup, sync, stolen disk) used on another machine | `session.db` limited to your user; Windows EFS for the store folder by default; full disk encryption advised on macOS and Linux; message fields in `wa.db` encrypted with a key that only this user on this machine can unwrap; `session_replaced` and `device_added` events when the copy is used | Partly: on macOS and Linux without disk encryption a copied `session.db` still works until the device is removed on the phone | `TestRestrictedPermissions` (fsutil), `TestApplyEFS`, `TestEFSStatusCallWorks`, `TestDPAPIOtherUserOrMachineCannotOpen`, `test_dpapi_round_trip_and_other_user`, `TestSessionEventsAreRecorded`, `TestDeviceListChanges`, `TestStatusShowsSecurityEventsAndProtection`, `test_bridge_status_reports_security_events` |
| Session theft by another local user | Access list (Windows) or 0700/0600 (macOS, Linux) on every start; DPAPI user scope; key files refused when group or others can read them | Mitigated | `TestRestrictedPermissions`, `TestParseAndReadKeyFile`, `test_key_file_rules` |
| Session theft by malware or an administrator running as your user | None beyond detection: such code can read the store, ask the keystore for keys and call the API | Out of scope | Events as above |
| Store key or API token read from the process list or a file | Keys and tokens kept in DPAPI, Keychain or Secret Service; passed to `security` and `secret-tool` on standard input only; the plain `store/api.token` moved into the keystore and wiped | Mitigated | `TestCLIBackendsWithFakePrograms` (checks argument lists), `test_cli_backends_with_fake_programs`, `TestTokenMovesIntoKeystore`, `TestTokenWhenTheKeystoreIsDown` (no silent new plain token), `test_token_from_keystore_then_file` |
| Plain text left behind when encryption starts | In-place migration in one transaction with a checked plain copy, file rewritten (VACUUM, WAL truncated), copy wiped; Python wipes copied text in `insight.db` | Mitigated (SSD and copy-on-write blocks: accepted, full disk encryption advised) | `TestPlainStoreIsEncryptedInPlace`, `TestFailedMigrationKeepsPlainStoreAndCopy`, `TestLeftoverPlainCopyIsWipedAtNextStart`, `TestCompactionBlockedByReaderIsRetried`, `TestMigrationWithAnIdleReaderOpen`, `TestExclusiveLockKeepsReadersOutAndIsReleased`, `test_store_encrypted_by_the_go_bridge_opens_here`, `test_wipe_leaves_no_text_in_the_file` |
| A sealed value moved to another row or column by someone who can write the database | AES-GCM associated data names table, column and row (`wae2:`), so a moved value does not open; old `wae1:` values stay readable | Mitigated | `TestValuesAreBoundToTheirRow`, `TestDerivedTextIsBoundToItsSource`, `TestAADVectorsAndBinding` (shared vectors, also read by the Python tests) |
| The MCP server (or its container) needs the session file | The bridge copies names and the LID map into `wa.db` (`wa_contacts` sealed, `wa_lid_map`); `session_file` can live on a volume only the bridge mounts | Mitigated | `TestDirectoryIsCopiedIntoWaDB`, `TestSchemaFiveDirectoryAndReaderVersion`, `TestAbsoluteSessionFile` |
| Key or passphrase files readable by other accounts | At most 4 KiB; mode 0600 or 0400 on Unix; on Windows an access list with the user and SYSTEM only | Mitigated | `TestParseAndReadKeyFile`, `TestPassphraseFromFile`, `test_key_file_rules` |
| Wrong or missing key, mode switched off | The kind of key is recorded in the database; wrong keys, a missing keystore item and mode `off` on an encrypted store stop with a message; no silent fallback to plain text | Mitigated | `TestEncryptedStoreWithModeOffIsRefused`, `TestKeyPlanModes`, `TestPassphraseStoreKeepsWorkingUnderKeystoreMode`, `test_keystore_and_keyfile_stores_open`, `TestEncryptionAtRest` |
| Key loss (Windows password reset by an administrator, deleted profile or keychain item) | Documented; mode `keyfile` for users who need an offline copy of the key | Accepted | Docs: [Encryption and keys](../guides/encryption.md#moving-a-store-and-recovery) |
| Other local processes calling the API | Bearer token compared in constant time; token not in logs | Mitigated | `TestAuthAndHost`, `TestStartLogsHoldNoSecrets` |
| Browser DNS rebinding against the API or the login window | Host header must match the listen address | Mitigated | `TestAuthAndHost`, `TestLocalhostAliasAccepted`, `TestOneTimeTokenExchange` |
| CSRF from a web page | API needs the `Authorization` header, which a page cannot add cross-origin without CORS, and the API sends no CORS headers; the login window uses an HttpOnly SameSite=Strict cookie plus a header token on POST | Mitigated | `TestAuthAndHost`, `TestPageUsesCookieForEvents`, `TestOneTimeTokenExchange` |
| Login link copied from a log or terminal history | One-time token, spent on first use, valid for 10 minutes, at most 5 open; sessions end after 12 hours; not written to redirected output | Mitigated | `TestPrintLoginURL`, `TestNewLinkIsSingleUseToo`, `TestLoginSecretsExpire` |
| Routes added by an embedding program take over bridge paths or skip the token for remote callers | Patterns are tried against bridge paths with every method, so wildcards are caught; routes without a token answer loopback peers only | Mitigated | `TestWildcardRoutesCannotTakeBridgePaths`, `TestOpenRoutesNeedALoopbackPeer`, `TestExtraRoutes` |
| Remote mode: requests without a valid token | Bearer token on every `/mcp` request; static tokens of 256 random bits stored as HMAC-SHA256 with a server pepper; OAuth access tokens valid 60 minutes and bound to this server's `/mcp` resource; a revoked token fails on the next request | Mitigated | `test_without_or_with_a_wrong_token_401`, `test_revoked_token_401`, `test_tokens_are_stored_hashed`, `test_token_store`, `test_confidential_client_secret` |
| Remote mode: OAuth code or token theft, consent CSRF, open redirects | PKCE S256 only; exact redirect URI match; codes valid 2 minutes and once; consent bound to the starting browser by a cookie plus a derived form value; owner approval by admin password (keyed hashes, per-address backoff) or a one-time link; a reused code or rotated refresh token revokes the grant; RFC 7009 revocation; errors of never-approved clients are not redirected | Partly: in link mode whoever reads the server log can approve | `test_full_flow_with_rotation_and_revocation`, `test_reused_refresh_token_revokes_the_grant`, `test_reused_code_revokes_its_tokens`, `test_authorize_refusals`, `test_approved_client_gets_error_redirects`, `test_consent_wrong_password_deny_and_other_browser`, `test_consent_password_backoff_per_address`, `test_approval_link_mode`, `test_mcp_sdk_oauth_client` |
| Remote mode: rogue client registration | Redirect URIs only from `server.oauth.redirect_uri_prefixes` (default: the documented Claude callbacks and loopback), no user info or fragment; registrations per address and hour; unapproved clients capped at 10 for an hour, oldest dropped; `max_clients` counts approved clients; the consent page shows registration age and address; registration alone gives no access | Mitigated | `test_registration_limits`, `test_redirect_uri_rules`, `test_default_redirect_prefixes_and_consent_details`, `test_registration_cap_counts_approved_clients_only`, `test_registration_limit_per_address` |
| Remote mode: brute force and flooding | Rate limits per token, per address and for OAuth and failed bearer checks; an address that used up the failed-check budget is refused on `/mcp`; password lockout after 10 failures; request size limit; session cap | Partly: limits are kept in memory and reset on restart | `test_rate_limit_per_token_and_failed_auth`, `test_rate_limit_per_ip`, `test_request_size_limit`, `test_buckets_refill` |
| Remote mode: DNS rebinding and cross-site requests against the HTTP server | Host allow-list (421), Origin allow-list (403), no CORS unless `server.cors_origins` is set, security headers | Mitigated | `test_host_and_origin_allow_lists`, `test_cors_only_when_configured`, `test_health_and_headers` |
| Remote mode: plain HTTP on the network | `serve --http` refuses a non-loopback address unless `server.public_url` is https (TLS proxy) together with `server.trusted_proxies`, and then accepts only those peers and loopback; or `--insecure-lan`, which logs a warning; OAuth needs https or loopback | Mitigated | `test_https_guard_refuses_plain_lan`, `test_insecure_lan_flag_warns`, `test_https_public_url_needs_trusted_proxies`, `test_https_public_url_allows_any_interface`, `test_peers_outside_trusted_proxies_are_refused`, `test_transport_guard` |
| Remote mode: secrets and chat ids in the HTTP server log | Access log with method, path, status and address only, no query strings or headers; tokens never logged; the HTTP client loggers (httpx, httpcore) stay at WARNING in every serve path, so bridge URLs with JIDs are not logged; approval links logged on purpose in link mode | Mitigated | `test_access_log_has_no_secrets`, `test_http_client_logs_no_urls` |
| Remote mode: login page behind a proxy | `login.public.url`: only with the one-time link from `wa-bridge login-url`, Secure HttpOnly SameSite=Strict cookie under the path prefix, only the public Host accepted, no local window | Partly: whoever opens a fresh link while the bridge waits for a login could link their own phone | `TestPublicWindowBehindProxy`, `TestPublicWindowSecureCookie`, `TestLoginPublicValidation` |
| Remote mode: bridge API reachable from other machines | Warning at start for non-loopback addresses; in Docker the API stays on 127.0.0.1 inside the bridge's network namespace, shared only with the MCP server; `/health` needs no token and shows only `connected` and `logged_in` | Mitigated | `TestListenWarning`, `TestHealthNeedsNoTokenAndShowsNoData`, `TestServeHealthForPreview` |
| Prompt injection through message text, transcripts, file text, reactions | Server instructions and per-tool notes mark the text as untrusted; sending off by default; sends approved through MCP elicitation; `confirm=true` only with `sending.allow_confirm_flag` | Partly: a model can still be misled; the user's approval is the real check | `test_untrusted_notes_and_push_names`, `test_send_asks_the_user_through_elicitation`, `test_no_elicitation_needs_allow_confirm_flag`, `test_prompts_wrap_untrusted_data` |
| Prompt injection or spoofing through push names and file names | Push names shown with `~` and never used as send targets; file names from senders sanitized | Mitigated | `test_send_target_never_uses_push_name`, `test_untrusted_notes_and_push_names`, `TestSafeName`, `TestFileNames` |
| Path traversal: sending files from the store, the config or the key file; links and junctions; received names; zip entries | Allowed folders only; store, config and key file always denied, also through hard links and junctions; sanitized names with the message id; zip entries that leave the folder refused | Mitigated | `TestStoreFilesCannotBeSent`, `TestStoreAndConfigAreNeverSent`, `TestHardLinksAndJunctionsRefused`, `TestEncryptionModesAndCompat` (key file denied), `TestWebhooksPerAccountAndDeniedStores` (stores of all accounts denied), `TestAbsoluteSessionFile`, `TestSafeName`, `TestUnsafeEntriesRefused`, `test_file_stem_keeps_non_latin_names_apart` |
| SQL injection | All values are bound parameters; the only built SQL uses fixed table and column names; search runs `instr` on folded text or a Python function, so `%` and `_` are plain characters; the MCP server opens `wa.db` read-only | Mitigated | `TestUnicodeCaseInsensitiveSearch` (`50%`, `R_S`), `test_casefold_search`, `test_store_is_opened_read_only` |
| Zip bombs and large files | Archives listed, never unpacked to disk; limits on members, total size and compression ratio; attachment and import size caps; compressed HTTP bodies capped after decompression | Mitigated | `test_zip_inventory_and_bomb`, `TestZipBombRefused`, `TestArchiveLimits`, `TestFetchSizeLimit`, `test_gzip_body_is_capped_after_decompression` |
| SSRF through links in messages | Only `https://docs.google.com`; no credentials, non-default ports or non-public addresses; redirects re-checked; the checked address is the one connected to | Mitigated | `test_guard_private_dns_and_host_list`, `test_redirect_to_other_host_is_refused`, `test_embedded_private_addresses_refused` |
| SSRF or data leaks through webhooks and HTTP backends | Only URLs you configure; redirects not followed; signed requests | Accepted (you choose the receivers) | `TestRedirectsAreNotFollowed`, `TestSignCoversTimestampDeliveryAndBody`, `TestEnvelopeNamesTheAccount` |
| Secrets in logs | Logs name where a key lives, never the key, the token, the passphrase or message text; numbers masked; URLs redacted | Mitigated | `TestStartLogsHoldNoSecrets` (scans the start log for text, passphrase, token, keys, webhook secret), `test_logs_hold_no_secrets`, `TestLogsHideNumbersAndText`, `TestScrubPathsAndRedactURL`, `TestPrintLoginURL`, `test_examples_are_masked_and_secret_free` |
| Dependency vulnerabilities | Pinned versions (`go.sum`, `uv.lock`); `pip-audit` on 2026-11-23 over the 110 pinned Python packages (all extras): no known vulnerabilities; `govulncheck` not run, because it needs the online database at vuln.go.dev and the toolchain here is offline | Partly | Run `govulncheck ./...` in `bridge/` and `uvx pip-audit` before a release |
| Crash or power loss: data loss or a corrupt store | SQLite WAL with one writer connection; files written through a temporary file and a rename; scheduled sends marked before sending so they are not repeated; encryption migration in one transaction; an in-memory session mode rejected (see [Why the session is not kept in memory only](../security.md#why-the-session-is-not-kept-in-memory-only)) | Mitigated | `TestWriteFileAndLock`, `TestInterruptedEntriesAreNotResent`, `TestShutdownFinishesInflightSend`, `TestServeWaitsForRunningRequests`, `TestFailedMigrationKeepsPlainStoreAndCopy`, `test_migrations_are_atomic_and_repeatable` |
| Leftovers after a crash: partial downloads, import uploads, a replaced or cut file reused, bridges left behind by a killed `run-all` | Temporary files wiped on failure and swept at start; reuse only after the SHA-256 (or the zip CRC-32) matches; Pdeathsig on Linux and a kill-on-close job object on Windows | Mitigated | `TestSweepTempRemovesOnlyLeftovers`, `TestReplacedFileIsDownloadedAgain`, `TestSameEntryChecksTheCRC`, `TestChildIsAttachedForCleanup` |
| A bridge with a configuration or key error restarted in a loop | Exit code 78 for such errors; `run-all` does not restart it | Mitigated | `TestFatalExitIsNotRestarted`, `TestKeyErrorsExitWithTheFatalCode` |
| Two bridges on one store | Exclusive lock file; a copy used elsewhere raises `session_replaced` | Mitigated | `TestImportRefusedWhileBridgeHoldsStore`, `TestSessionEventsAreRecorded` |
| A different account in a store | The account is recorded at the first link; another one is refused and unlinked, and an event is recorded | Mitigated | `TestAccountBinding`, `TestAccountMismatchIsRecorded` |
| Disk growth | Pending edits and reactions pruned by age and count; the sent log pruned after two days; attachment size limit; analytics cache and closed tasks expire; security events capped at 20. Messages are kept, by design | Partly | `TestPruningAndReactionCap`, `TestReactionPruningUsesTheIndex`, `TestPendingCountCap`, `TestFetchSizeLimit`, `test_retention_for_cache_and_closed_tasks`, `TestStatusShowsSecurityEventsAndProtection`, `TestSchemaFiveDirectoryAndReaderVersion` (WAL capped at 64 MiB) |
| Deleted messages stay on disk | Hidden from reads unless asked; documented | Accepted | Docs: [What is stored where](../security.md#what-is-stored-where) |
| whatsmeow or WhatsApp protocol changes | whatsmeow pinned in `go.mod`; "client outdated" shown in the login window; the Python reader checks its copy of the whatsmeow schema; a newer `wa.db` schema is refused | Accepted (update the bridge) | `test_session_fixture_matches_whatsmeow_schema`, `TestNewerSchemaRefused`, `TestDeviceListChanges` (own devices addressed by LID) |
| Account restrictions by WhatsApp | Sending off by default; limits, quiet hours and human-like pacing | Out of scope | `TestConcurrentSendsRespectLimits`, `TestQuietHours` |

## Not verified here

- The macOS Keychain and Linux Secret Service backends are tested with fake `security` and `secret-tool`
  programs on `PATH`, not against a real keychain. The fakes follow the documented exit codes (44 for a
  missing keychain item, 1 without output for a missing Secret Service item).
- Windows EFS is tested with fake system calls, so the tests never create an EFS certificate on the test
  machine. Only the read-only status call runs for real.
- The Linux parent-death signal of `run-all` is set but was only built, not run, here (the tests ran on Windows, where the job object is tested).
- No fuzzing has been done.
