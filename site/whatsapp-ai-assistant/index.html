Daily activity guide

A WhatsApp assistant for your day

A WhatsApp AI assistant connected to WA MCP can tell you who needs a reply, what you promised and which messages are scheduled today. Ask “What are my tasks today?” and the assistant can call my_day, a local tool that organizes requests from your chats using plain rules.

Start with the message behind a task

A short daily list is easier to act on if each item points back to the original exchange. The daily tool returns a chat, message ID, time and a short line of context for each item. Ask the assistant to show the messages around a request before deciding that it still needs a reply.

The project's example includes an open invoice request, a promise to send photos, a question in a book club chat and a scheduled reminder. These are different kinds of work. A scheduled send is already queued in the bridge, while an unanswered question may only require a decision. The overview also includes missed calls that have not been returned.

Set the date and scope

With no date supplied, my_day uses today. Ask for a particular date to review another day, or provide the chat to focus on one conversation. With several configured accounts, a call without an account combines the overview from all numbers and labels the results. Supply an account name for a briefing limited to that number.

Check the history before relying on an empty overview. List a few recent conversations and their last message dates. If the store has little history, ask to page back in one chat with the phone online. When a sync reports incomplete work, another call can continue it. Imported archive messages are excluded from task detection unless you explicitly include them.

Understand the task tracker

Use tasks_overview to find open tasks, task_detail to see the steps of a task and which_task to trace an individual message to its task. A detail view can show why a message was attached to an existing request. For changes over a recent period, ask what moved in the last day with whats_new.

The tracker distinguishes new, in progress, waiting, done, cancelled and stale tasks. An inactive open request becomes stale after 60 days with the default settings. It disappears from the daily list but remains in the tracker until the retention period passes. If a recent request is missing after messages changed, refresh the tracker and check the wording in the source chat.

Teach the rules your working vocabulary

The built-in word lists are English. Extend tasks.keywords in your configuration with the phrases your group uses for requests, urgent work and deliverables. A trailing asterisk matches word endings. Adding a phrase for “updated invoice”, for example, lets you describe a recurring deliverable in the same terms that people use in the chat.

In a group, a message must mention you, reply to you or use one of your names to count as addressed to you. Configure the names people actually use under insight.my_names. Set project keywords and relevant chats if generic terms mix unrelated work. Watched words provide a separate way to find mentions across messages, transcripts and extracted file text.

Choose who writes the summary

Task detection works without a background model. Your client can phrase the structured result as a short briefing. If you configure a separate provider and request summary=true, the provider receives selected fields including names, due hints and clipped context. A remote provider therefore sees that input. Leave the optional provider off to use the rule-based result alone.

Questions

Does a daily briefing send replies?

Reading the overview does not send a WhatsApp message. Sending is a separate capability that starts disabled. A scheduled item in the overview refers to a send already scheduled in the bridge.

Can a voice note contribute to a task?

Yes. Once a voice note has a transcript, its text becomes available for task detection and search. Ask for transcription in the relevant chat before looking for spoken requests.
