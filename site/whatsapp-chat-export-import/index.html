Export a WhatsApp chat for AI search

Export a WhatsApp chat for AI search from the phone, then preview its TXT or ZIP file in WA MCP. Check the destination, date order and sender mapping before adding the conversation to your local store.

Export a single conversation

On Android, open the conversation and choose More and then Export chat from its menu. On iPhone, tap the chat name at the top and select Export chat. Choose whether to include media and transfer the file to the computer that holds the bridge. An export with media can cover a shorter stretch of history, so check its earliest date.

A plain text file contains the conversation lines. A ZIP can supply the attachment files as well as their captions. The importer recognizes the Android and iPhone layouts, multiline messages and several clock formats. System notices and media placeholders are counted separately from ordinary messages. Replies, edits, deletions and reactions are absent from the export format.

Preview the destination and senders

Choose the chat by phone number with country code, WhatsApp ID or an exact stored title. When a title matches several chats, use the ID from the candidate list. For a person with both phone and LID entries, choose the chat that list_chats shows with messages. Duplicate checking compares with the specific destination you chose.

Pass your own sender name exactly as it appears in the file through the me option. The reader can infer some direct-chat identities, but a group export can have names with no unique match in your address book. Map a sender explicitly when necessary. Inspect the proposed identities in the dry run before relying on outgoing and incoming labels.

Check dates before writing

An export has no time zone. Give the zone where it was created, especially if your server is somewhere else. A date such as 04/05 can mean April 5 or May 4. The reader considers the fields and order of the messages, and reports how it selected the date order. If it could only assume an order, set dmy, mdy or ymd explicitly.

A dry run reports the time range, proposed message count, duplicates, missing media and warnings. Compare the first and last times to what you see on the phone. Check skipped lines and sender mappings as well as the total. Keep the same time zone for subsequent imports because a different offset changes the generated message IDs.

Run the import

In the v0.2.0 checkout, include history alongside core in mcp.toolsets and restart the MCP server to expose the import tool.

With the bridge running, ask the assistant to use import_chat_export on a file in the configured downloads or exports directory, or another allowed directory. Use dry_run first, then repeat with the same arguments and dry_run disabled. The HTTP API also accepts a form upload. For the command line importer, stop the bridge before opening the store directly. 

wa-bridge import-export --file "chat.zip" --chat 15550100002 --dry-run

Messages receive stable IDs derived from their contents and source information. A repeat of the same file skips records already imported. The reader also checks for a matching synced message near the same time. If you first imported text and later supply a ZIP, a placeholder can acquire its file without adding another copy of the message.

Find the imported history

For an output file you can read outside WhatsApp, use export_chat to write a Markdown transcript. It can include the time, sender, replies, transcripts and media paths. That output serves a different purpose from the phone's TXT or ZIP input. The tool reports a message count and a path in the exports directory.

Search the destination chat for a phrase from the old conversation and ask for the messages around it. The result carries imported: true. Imported messages are marked read and are visible to search and analytics. The original export remains a separate file outside database field encryption, so keep it in a private location.

Questions

How do I export a WhatsApp chat to AI without uploading the whole ZIP?

Use Export chat on the phone and import the file into the local WA MCP store. Let the assistant request a small result from that store. A hosted client processes the tool results it receives.

Will old requests appear in today's task list?

By default the task tracker, task detection and my_day skip imported messages. Enable tasks.include_imported when you intend old exports to contribute to those results.

Does an import notify anyone?

No. The import updates your local store. It emits no webhook event and does not deliver a message or attachment to anyone in the original conversation.
