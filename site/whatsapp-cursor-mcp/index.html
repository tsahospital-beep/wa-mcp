WhatsApp MCP for Cursor

Add WA MCP to Cursor using the install link, set the absolute path of the linked bridge configuration and enable the server in Cursor Settings. Cursor can then search WhatsApp messages, read a thread or ask for a daily overview through its MCP tools.

Install the server in Cursor

Install uv on the computer that runs Cursor, then use the Cursor button below. The link configures uvx to launch the published Python server and includes the SDK extras for encryption and file text. It sets up a command for the editor to run when it needs the server. Your phone is linked separately by the Go bridge.

Add to Cursor

Set WA_MCP_CONFIG in the environment that Cursor inherits to the absolute path of the bridge's config.json. Restart Cursor after changing that environment. Alternatively, add the config option and path to the installed arguments. This matters when you switch workspaces: the editor's current directory can change while the WhatsApp store stays in the same place.

Choose the scope of the configuration

For access across projects, edit the mcp.json file in the .cursor directory under your home folder. For one project, use .cursor/mcp.json in that project. Both locations accept an mcpServers object. If you prefer to inspect exactly what Cursor will run, enter the following configuration manually and replace CONFIG_FILE with your local path. 

{
  "mcpServers": {
    "wa-mcp": {
      "command": "uvx",
      "args": [
        "--from",
        "wa-mcp-server==0.1.0",
        "--with",
        "wa-mcp-sdk[encryption,files]",
        "wa-mcp",
        "--config",
        "CONFIG_FILE"
      ]
    }
  }
}

Open Cursor Settings and look under MCP for wa-mcp. Switch the server on. A source checkout can run through uv with its repository directory, while a persistent pipx installation can launch wa-mcp directly. Use the command for the installation you actually have. In particular, an editor started from the desktop may need an absolute path to the executable.

Trace a request from the editor

Start with a read that needs no outbound message. Ask Cursor to find the last mention of an invoice and show the messages immediately before and after it. The lookup searches text already stored by the bridge. Once Cursor has the chat and message ID, it can fetch the surrounding exchange and distinguish the original request from a later correction.

For work split across phone numbers, ask for the configured accounts first. Specify the intended account when looking for a project conversation. The server exposes one set of tool names with an optional account argument. Each number has its own bridge and store, so a missing result may mean the search used the default number.

Diagnose an empty tool list

Run the published command with the help flag in a terminal to check the executable and package before debugging a chat. If Cursor lists the server but tools fail, ask for bridge_status. A readable database means Cursor can reach stored messages. A disconnected bridge explains why an attachment download or a request for older messages cannot proceed.

A recent installation may have few conversations because the phone has only sent its first batch of history. Ask to list recent chats with their dates, choose one, then request older pages for that chat. Keep the phone online and repeat the request if the sync reports that its time budget expired with work remaining.

Connect Cursor to a hosted bridge

Cursor can also use the Streamable HTTP endpoint of a hosted deployment. Put its HTTPS URL ending in /mcp in the server entry and supply the Authorization bearer header. Create a token specifically for this device and keep the credential out of project files shared with other people. Revoking that token stops its next request without affecting tokens for other devices.

Questions

Does Cursor need the WhatsApp API token in its local configuration?

In the usual local setup the bridge and Python server obtain the token through the shared configuration and user keystore. A remote MCP token is a separate credential for a hosted endpoint.

Can I keep sending disabled?

Yes. The message lookup and context requests above only read your stored conversations. You can also extract document text and search transcripts without turning on the sending pipeline.
