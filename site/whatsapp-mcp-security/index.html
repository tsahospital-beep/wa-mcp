WhatsApp MCP security and account risk

WhatsApp MCP security depends on the linked session, the local store and the client that reads it. Field encryption is on by default. Review what leaves the machine before giving a client access to your chats.

Know what a copy reveals

The message database protects fields including message text, transcripts, reactions, attachment names and media keys. The default store key belongs to the operating system user running the bridge. A copy of protected fields requires access to that key. Chat identifiers, titles and timestamps remain readable, and a WhatsApp ID can include a phone number.

The linked-device database contains the keys used to connect to WhatsApp. Field encryption of messages does not cover that database. On Windows the bridge enables EFS for the store folder by default. On macOS and Linux, use full disk encryption for the session file. Media files, Markdown exports and original chat exports also need private storage and backup handling.

Choose how to hold the key

On Windows the default mode wraps the store key with DPAPI. On macOS the key lives in the login Keychain. Linux uses Secret Service through secret-tool. Run the Python server as the same user so it can read protected fields. The bridge also keeps its generated API token in the keystore under this configuration.

A headless machine may lack a desktop keystore. Use the documented keyfile mode with a restricted key file, or supply a passphrase. The container configuration uses a Docker secret for its key. Protect a separate backup of the key because the encrypted data needs it for recovery. An already encrypted store records what kind of key it expects.

Review what leaves your machine

A search can run against a local database while its results go to a hosted assistant. Choose a client whose handling of message content suits the account. Voice notes sent to a remote transcription endpoint leave the machine as audio. An optional remote vision provider receives the images you ask it to describe. Local OCR works without requesting a description.

The same distinction applies to daily summaries. The task detector uses rules locally. If you enable a provider and ask for a summary, it receives selected names, due hints and short context lines. Text recovered from a file, spoken in a recording or written in a chat is untrusted input. The server tells the client to treat it as content from other people.

Check outbound permissions

You can search and review history with sending switched off. If sending is enabled, a client that supports MCP elicitation asks for approval of the recipient and content. A client without that ability needs a separate setting to accept confirm=true. The model can supply this flag itself, so it provides a weaker approval check.

Quiet hours, limits and duplicate protection also apply to sends. By default attachment sending is restricted to the downloads and exports directories. The bridge denies sending the store and configuration files. These controls help limit what an enabled send tool can do. They do not remove the account risk of using the unofficial WhatsApp Web protocol.

Inspect a session warning

Ask for bridge_status and review its protection details and recent security events. The status endpoint retains the latest 20 session events, including a remote logout, another client using the session and changes to linked devices. A security webhook can deliver those events to a configured receiver. Review an unfamiliar linked device on your phone under Linked devices.

Questions

Can WhatsApp restrict an account using MCP?

Yes. WA MCP uses the unofficial WhatsApp Web protocol. A linked account can be restricted or banned even when sending limits are enabled.

How should I expose MCP to another device?

Use the documented remote mode with an HTTPS proxy and trusted proxy configuration. Give each device its own revocable token or use the supported OAuth flow with owner approval.

Can encryption protect a downloaded export?

Database field encryption applies to the stored message fields. A file written into the exports directory needs filesystem protection of its own. Include that directory when deciding how to protect backups.
