Architecture guide

How the WhatsApp MCP server works

The WhatsApp MCP server gives an assistant access to a linked account. A Go bridge collects messages and a Python server reads the store. The v0.2.0 source checkout exposes 11 core tools by default, with 53 across all toolsets.

Follow a message from phone to client

Link the bridge as a companion device from WhatsApp on your phone. It receives recent history after linking and continues to record new messages while it runs. It also applies edits, deletions and reactions. The result is a local SQLite database that a second process, the MCP server, can read when a client asks a question.

For example, ask for the last conversation about an invoice. The client can call list_messages with a search term and use the returned chat and message ID to retrieve the surrounding conversation. A request to download an attachment takes a different route. The server calls the bridge's authenticated HTTP API because the bridge owns the connection to WhatsApp.

Start with one linked account

Build the bridge with Go 1.26 or newer, or run the published bridge image. Copy the example configuration and start the bridge. Open Linked devices on your phone and scan the QR code in its login window. If the window does not open, the terminal also displays the code. The login window offers pairing by phone number when you cannot scan.

Install uv so your client can launch the Python server with uvx. Give it the absolute path of the same config.json that the bridge uses. Relative configuration paths can lead the client to look for an empty store in its working directory. Start with bridge_status and check three separate results: the database is readable, the bridge is connected and the phone account is logged in.

Choose a transport

On a desktop, the client starts the server as a child process and communicates over standard input and output. That requires no listening port for MCP. You can close the client between questions and leave the bridge collecting messages. When the bridge is stopped, database reads remain available from the stored history. Live operations such as asking the phone for another page require the connection.

For a server shared with remote clients, enable Streamable HTTP. Each request to the MCP endpoint needs a bearer token. A device can use its own revocable token, or an OAuth client can request approval from the owner. The deployment guide describes an HTTPS proxy, host checks and the addresses that may forward requests.

Add history and other numbers

A new link receives only the history that the phone supplies. For a specific conversation, request older pages back to a date. Keep the phone online and continue a time-limited sync if it returns an incomplete result. An existing WhatsApp text or ZIP export gives you another source for older messages. Preview the import before writing it into the selected chat.

Each additional number needs its own bridge, store and sending limits. One Python server can present all the configured accounts. Ask for list_accounts to see the available names, then pass an account to scope a tool call. The daily overview has a useful exception to the default selection: without an account argument it combines the day's items across numbers.

Decide what the client may see

Message text is encrypted in the database by default. The server reads it as the operating system user that holds the key and returns requested results to the assistant. Consider the client you choose and where it processes those results. Search and daily briefings work with sending disabled, so you can try both before deciding whether you want to enable outbound messages.

Questions

Which tools does the WhatsApp MCP server load?

The v0.2.0 checkout loads core by default. Add named groups to mcp.toolsets in config.json and restart the MCP server. For example, add history alongside core to make chat export and import available.

Is there a required background model?

No. The assistant interprets the tool results. Task detection uses local rules. A separately configured provider can add an optional summary or image description.

What license covers the project?

WA MCP is published under the MIT license. The implementation includes the Go bridge, Python SDK and Python MCP server.
