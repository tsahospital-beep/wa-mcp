Transcribe WhatsApp voice messages

Transcribe WhatsApp voice messages with a local speech engine or a configured HTTP endpoint. Run transcribe_chat_audio for one chat and search the resulting text alongside the original audio messages.

Choose where the audio goes

The default backend is faster-whisper, which can run on a CPU or an NVIDIA GPU. The openai-whisper option uses the reference implementation on PyTorch. For whisper.cpp, install the whisper-cli program and a ggml model. These choices let you process a recording on the computer where you run the transcription tools.

An HTTP backend accepts an OpenAI-compatible audio transcription endpoint. If you configure a remote address, that service receives the voice recording. A custom command is another option when you already have a speech engine. Specify its executable and arguments, use the file placeholder for the converted audio and have it print the transcript on standard output.

Prepare the backend

Install ffmpeg and ensure that the process launched by your assistant can find it. Set WA_MCP_FFMPEG to the executable path if it is outside the normal search path. Choose transcription.backend and transcription.model in the same config used by the MCP server. The default large-v3 model takes more memory and time than the small or medium choices.

From a source checkout, run the backend installer for your operating system. The download option fetches the model during setup so the first transcription does not have to fetch it. The scripts use uv sync with the inexact option to keep other installed extras. Use the same option when updating that environment to preserve the speech packages. 

scripts/install_whisper.sh --backend faster-whisper --model large-v3 --download

On Windows, use the PowerShell installer from the repository root. It accepts the backend and model as named parameters. After installation, start the client with the same project environment so the transcription tool can find both the backend and ffmpeg. 

scripts\install_whisper.ps1 -Backend faster-whisper -Model large-v3 -Download

Ask for get_bridge_status and inspect transcription_backend, transcription_ready and transcription_hint. Read the hint before testing a long recording. It can distinguish a missing program or package from a problem retrieving the voice note itself. When using a source environment with optional packages, make sure the client launches the server from that environment.

Transcribe one conversation

Start with one chat and a small limit. By default the tool covers the most recent 14 days. It downloads missing attachments through the bridge, converts the audio to 16 kHz mono WAV and divides longer recordings at quiet points. The selected backend transcribes each part and the tool joins the text in message order.

The tool stores the text, detected language and confidence with the original message. A configured language overrides detection. Otherwise the first chunk supplies the detected language. For a short or uncertain clip, earlier confident transcripts in the same conversation can supply a more likely language. This helps explain why a brief reply can inherit the chat's usual language.

Continue a long archive

Use full_archive to include older stored recordings and limit to bound the number handled per call. The time budget defaults to 120 seconds and allows up to 600. An incomplete result reports remaining clips. Repeat the call with force disabled so completed transcripts are skipped. Reserve force for recordings you intend to process again.

If a file has expired on WhatsApp's servers, the bridge can ask the phone to upload it again. The phone must be online and still have the file. A backend that is ready cannot transcribe audio that is unavailable. Check an individual recording before repeating an archive-wide request that keeps missing the same clips.

Questions

Can I transcribe WhatsApp voice messages locally?

Yes. Choose a local backend such as faster-whisper or whisper.cpp and install its dependencies. With an HTTP transcription provider, the selected audio goes to that endpoint.

How do I read the transcript afterward?

Ask for the original message with list_messages. Its transcript is shown inline. You can also search for a phrase you heard or inspect the conversation around the matching voice message.

Is the transcript protected at rest?

With default encryption, the transcript field is encrypted in the message database. Downloaded audio has separate filesystem protection needs. The assistant receives transcript text when it requests the message.
